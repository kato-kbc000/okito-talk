# セキュリティ更新の導入手順

**重要：このZIPはローカルでの静的修正です。Supabaseへの適用・本番動作確認はまだ行っていません。**

1. Supabaseのバックアップを取得する。
2. SQL Editorで `security_upgrade.sql` を実行する。既存のRLSを置き換えるため、**必ずステージング環境で検証**する。
3. 投稿の公開/フォロワー限定/非公開、非公開コミュニティ、DM既読、位置共有を複数アカウントで確認する。
4. プライベートコミュニティは新規参加時 `pending` になります。管理者による承認UI/APIは未実装のため、本番公開前に実装する。
5. 既存の `supabase_complete_setup.sql` や `supabase_policies.sql` を**後から再実行しない**（安全なRLSを上書きする可能性があります）。
6. `back/.env` と `.git` と `back/venv` は配布ZIPから除外しました。必要な値は安全な方法でローカルに再設定してください。秘密情報を過去に公開していた場合はローテーションしてください。

## 追加したもの
- `blocks` / `reports` テーブルと本人限定RLS
- 投稿公開範囲のRLS（公開/フォロワー/非公開/コミュニティ）
- 承認済みメンバー限定の位置情報RLS
- コミュニティへの自己承認・役職昇格の防止
- DM送信時のブロック判定、既読更新の限定RPC
- 位置共有前の確認ダイアログ、アイコン画像描画のHTML注入防止

## 未完了・要確認
- OCIサーバーへのデプロイとFastAPIへの移行
- 管理者の通報対応画面、ブロック操作画面、非公開コミュニティ承認フロー
- SQLの実DB適用検証、E2Eテスト、Storageポリシーの詳細監査
- 投稿・フォロー・DMなどのブラウザからの実機動作確認
- 既存の他テーブルのRLS監査（`supabase_complete_setup.sql` の古いポリシーには注意）

**公開前にこれらを完了してください。**
